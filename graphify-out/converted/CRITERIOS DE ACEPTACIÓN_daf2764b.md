## Sheet: Hoja 1
| HU | Criterio ID | Nombre del Criterio | Descripción y Condición de Aceptación | Comportamiento del Sistema ante Error |
| --- | --- | --- | --- | --- |
| HU-01 | CA-01.1 | Validez, unicidad y formato de correo | El sistema valida que el correo electrónico ingresado tenga un formato válido y no se encuentre repetido en la base de datos | Se genera la notificación: "El correo ingresado es inválido o ya se encuentra registrado" |
| HU-01 | CA-01.2 | Seguridad de contraseña | La contraseña debe tener una longitud mínima de 8 caracteres y almacenarse de forma encriptada | Se elimina el campo de "contraseña" y se despliega la notificación: "La contraseña no cumple con los requisitos mínimos de seguridad" |
| HU-02 | CA-02.1 | Autenticación y expiración | Con credenciales válidas, el sistema retorna un token JWT seguro con un tiempo de expiración definido (por ejemplo, en 24 hrs) | Con credenciales inválidas, se despliega una notificación: "Usuario o contraseña incorrectos" |
| HU-03 | CA-03.1 | Validación de Formato de numéro telefónico | El sistema valida que el formato del número telefónico sea estrictamente numérico y correcto para su posterior uso | El campo de texto muestra un error de validación y bloquea el botón de guardado, generando la notificación "El numero telefonico ingresado es incorrecto o no existe"  |
| HU-03 | CA-03.2 | Límite máximo de contactos | El sistema bloquea el intento de registrar un nuevo contacto si la cuenta ya tiene el límite de 5 contactos de emergencia guardados | El botón de "Añadir contacto" se deshabilita y se genera la notificación: "Límite máximo de contactos de emergencia alcanzado" |
| HU-04 | CA-04.1 | Límite mínimo de contactos | Se requiere confirmación explícita antes de eliminar con una notificación de verificación. El sistema bloquea la eliminación si es el único contacto registrado, exigiendo mínimo 1 activo | Se despliega una notificación de alerta: "Debe mantener al menos un contacto activo en su red de auxilio. Se recomienda editar el contacto activo" |
| HU-05 | CA-05.1 | Restricción de longitud de mensaje | El mensaje de emergencia personalizado del usuario se fija a un máximo de 160 caracteres | El campo de texto en el sistema se trunca automáticamente al momento que se alcanzan los 160 caracteres |
| HU-06 | CA-06.1 | Confirmación de evento SOS | La interfaz exige mantener presionado el botón SOS (o boton asignado) continuamente por 2 segundos para generar un llamado de emergencia | Ignora toques rápidos o accidentales, en casos puntuales se notificará al usuario |
| HU-07 | CA-07.1 | Fallback de geolocalización | El sistema extrae la latitud/longitud de la ubicación del chip. Si el hardware no responde en menos de 3 segundos, se adjunta la última ubicación guardada como respaldo | En caso de una respuesta muy lenta o nula respuesta de la ubicación, se envía la ultima ubicación registrada indicando que corresponde a la última ubicación conocida del usuario |
| HU-08 | CA-08.1 | Transmisión de notificación | La notificación (al realizarse un llamado de emergencia) que contiene el enlace de ubicación y el mensaje personalizado, debe enviarse exitosamente a la totalidad de los contactos asignados  | Si un envío de alerta falla por problemas del proveedor, el sistema reintenta y guarda el error en la bitácora. |
| HU-09 | CA-09.1 | Límite de cuentas dependientes | La cuenta principal validada solo puede vincular un limite de 5 cuentas secundarias, considerando tambien el pago de añadir una o mas cuentas | Se genera la notificación: "No posee cupos disponibles para vincular nuevos usuarios dependientes" |
| HU-10 | CA-10.1 | PIN numérico exacto de 4 dígitos. Tres intentos fallidos bloquean la acción por 5 min. | El PIN debe ser numérico y exactamente de 4 dígitos, dentro del sistema se tolerarán un máximo de tres intentos fallidos antes de aplicar un bloqueo temporal | Al tercer intento fallido del PIN, se despliega la notificación: "Por seguridad, se ha bloqueado el intento de acceso por 5 minutos debido a intentos fallidos reiterados" |
| HU-11 | CA-11.1 | Cifrado en reposo AES-256 de datos médicos | Las fichas médicas ingresadas por los usuarios se almacenan en la base de datos utilizando un cifrado seguro AES-256 | Si ocurre un fallo en el cifrado, el sistema aborta el guardado y emite un error de sistema estándar |
| HU-12 | CA-12.1 | Bloqueo de visibilidad de ficha | El acceso a los datos médicos se niega automáticamente cuando el usuario desactiva la alerta con su PIN y define el estado como "Emergencia Finalizada" | Si un contacto intenta abrir el enlace post-emergencia, se redirigirá a una pantalla con el mensaje: "Emergencia finalizada. Acceso revocado" |
| HU-13 | CA-13.1 | Renderizado de panel administrativo restringido | El sistema verifica que el rol del usuario cumpla con el de ADMIN en el backend antes de permitir el renderizado de los datos y el historial. | Si se realiza un ingreso no autorizado, se redirige al usuario al inicio de sesión y se genera la notificación: "Acceso denegado. Permisos insuficientes" |
