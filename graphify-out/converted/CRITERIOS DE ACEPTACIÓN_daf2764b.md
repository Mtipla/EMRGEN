## Sheet: Hoja 1
| HU | Criterio ID | Nombre del Criterio | Descripción y Condición de Aceptación | Comportamiento del Sistema ante Error |
| --- | --- | --- | --- | --- |
| HU-01 | CA-01.1 | Validez, unicidad y formato de correo | El sistema valida que el correo electrónico ingresado tenga un formato válido y no se encuentre repetido en la base de datos | Se genera la notificación: "El correo ingresado es inválido o ya se encuentra registrado" |
| HU-01 | CA-01.2 | Seguridad de contraseña | La contraseña debe tener una longitud mínima de 8 caracteres y almacenarse de forma encriptada | Se elimina el campo de "contraseña" y se despliega la notificación: "La contraseña no cumple con los requisitos mínimos de seguridad" |
| HU-02 | CA-02.1 | Autenticación y expiración | Con credenciales válidas, el sistema retorna un token JWT firmado por el backend con expiración de 1 hora. El cierre de sesión elimina dicho token | Con credenciales inválidas, se despliega una notificación: "Usuario o contraseña incorrectos" |
| HU-03 | CA-03.1 | Validación de formato de número telefónico (E.164) | El número se normaliza y valida en formato E.164 (por ejemplo, +56 9 1234 5678; máximo 15 dígitos). No se permite registrar un número duplicado en la lista ni el número propio del usuario. | El campo muestra un error de validación, bloquea el botón de guardado y genera la notificación "El número telefónico ingresado no tiene un formato válido" |
| HU-03 | CA-03.2 | Límite máximo de contactos | El sistema bloquea el intento de registrar un nuevo contacto si la cuenta ya tiene el límite de 5 contactos de emergencia guardados | El botón de "Añadir contacto" se deshabilita y se genera la notificación: "Límite máximo de contactos de emergencia alcanzado" |
| HU-04 | CA-04.1 | Límite mínimo de contactos | Se requiere confirmación explícita antes de eliminar con una notificación de verificación. El sistema bloquea la eliminación si es el único contacto registrado, exigiendo mínimo 1 activo | Se despliega una notificación de alerta: "Debe mantener al menos un contacto activo en su red de auxilio. Se recomienda editar el contacto activo" |
| HU-05 | CA-05.1 | Restricción de longitud de mensaje | El mensaje de emergencia personalizado del usuario tiene un máximo de 160 caracteres, validado en el frontend y en el backend. | La interfaz impide escribir más de 160 caracteres y muestra un contador que cambia a rojo al llegar al límite; el backend rechaza mensajes de más de 160 caracteres. |
| HU-06 | CA-06.1 | Confirmación de evento SOS | La interfaz exige mantener presionado el botón SOS (o botón asignado) continuamente por 5 segundos para generar un llamado de emergencia en el perfil predeterminado de personas mayores o usuarios con acceso limitado; la duración es configurable según el tipo de usuario (valor para el resto de perfiles pendiente de confirmar) | Ignora toques rápidos o accidentales, en casos puntuales se notificará al usuario |
| HU-07 | CA-07.1 | Fallback de geolocalización | El sistema extrae la latitud/longitud de la ubicación del chip. Si el hardware no responde en menos de 3 segundos, se adjunta la última ubicación guardada como respaldo | En caso de una respuesta muy lenta o nula respuesta de la ubicación, se envía la ultima ubicación registrada indicando que corresponde a la última ubicación conocida del usuario |
| HU-08 | CA-08.1 | Transmisión de notificación | Por cada contacto asignado, el sistema registra al menos un intento de envío con su estado (PENDIENTE, ENVIADO o FALLIDO), número de intentos y hora exacta. El criterio se cumple cuando el 100 % de los contactos tiene un intento registrado y un estado final. | Si un envío falla por problemas del proveedor, el sistema reintenta con espera incremental y registra el error por destinatario; el usuario ve cuántos contactos fueron notificados. |
| HU-09 | CA-09.1 | Límite de cuentas dependientes | La cuenta principal validada solo puede vincular un limite de 5 cuentas secundarias, considerando tambien el pago de añadir una o mas cuentas | Se genera la notificación: "No posee cupos disponibles para vincular nuevos usuarios dependientes" |
| HU-10 | CA-10.1 | PIN numérico exacto de 4 dígitos. Tres intentos fallidos bloquean la acción por 5 min. | El PIN debe ser numérico y exactamente de 4 dígitos y se almacena como hash, dentro del sistema se tolerarán un máximo de tres intentos fallidos antes de aplicar un bloqueo temporal que corre un contador dentro del servidor por cuenta | Al tercer intento fallido del PIN, se despliega la notificación: "Por seguridad, se ha bloqueado el intento de acceso por 5 minutos debido a intentos fallidos reiterados" |
| HU-11 | CA-11.1 | Cifrado en reposo AES-256 de datos médicos | Las fichas médicas ingresadas por los usuarios se almacenan en la base de datos utilizando un cifrado seguro AES-256 | Si ocurre un fallo en el cifrado, el sistema aborta el guardado y emite un error de sistema estándar |
| HU-12 | CA-12.1 | Bloqueo de visibilidad de ficha | Una ves terminada la emergencia o despues de cierto tiempo, los datos medicos quedan invisibles de forma automatica. | Si un contacto intenta abrir el enlace post-emergencia, se redirigirá a una pantalla con el mensaje: "Emergencia finalizada. Acceso revocado" |
| HU-13 | CA-13.1 | Renderizado de panel administrativo restringido | El sistema verifica que el rol del usuario sea Administrador en cada endpoint del panel administrativo antes de permitir el renderizado de los datos, informes y el historial. Y responde con error 403 a cualquier otro rol que intente ingresar. | Si se realiza un ingreso no autorizado, se redirige al usuario al inicio de sesión y se genera la notificación: "Acceso denegado. Permisos insuficientes" |
| HU-14 | CA-14.1 | Ciclo de vida de una alerta | La alerta solo puede estar en los estados (ACTIVA, FINALIZADA, EXPIRADA). El usuario emisor (con su sesión activa) puede finalizar la alerta ingresadno su PIN. Si esta no es finalizada manualmente, esta pasa a EXPIRADA pasadas 24 horas desde la activación | Si la emergencia ya no está ACTIVA y se intenta finalizar, se rechazará entregando el mensaje "La alerta ya fue finalizada" y no cambiará el estado de la alerta |
| HU-15 | CA-15.1 | Cambio de contraseña/credenciales | El cambio de contraseña exige el correo electronico del usuario (activo) para realizar la recuperación | Se rechaza el cambio si la contraseña no cumple con el formato correcto solicitado, entregando el mensaje "No fue posible cambiar la contraseña. Verifique el formato ingresado" |
| HU-16 | CA-16.1 | Compra de plan o cupos | La compra se confirma solo cuando la pasarela de pago (Paypal) aprueba la orden. La compra se registra en la base de datos, al igual que se actualizan los cupos del usuario una vez por orden, el precio en USD utiliza el valor extraudo por el servicio externo Mindicador | El sistema no procede con el pago, no se genera la actualización de los datos y muestra el mensaje "El pago no pudo completarse, intente nuevamente" |
| HU-17 | CA-17.1 | Numeros oficiales de emergencia | El sistema muestra los numeros de los servicios de emergencia (131, 132, 133) y con un acceso directo para realizar una llamada directa a dichos servicios, se indica que el sistema no notifica ni llama a estos servicios automaticamente 
 | Si el dispositivo no puede realizar llamadas, se limitará a mostrar los numeros para una marcación manual |
| HU-18 | CA-18.1 | Solicitud de soporte | Un formulario con nombre, correo valido, categoria y descripción (maximo 500 caracteres) genera un ticket con identificador y estado inicial visible para el usuario | Los formularios incompletos o con correo invalido no se envían y se indica que campos deben ser corregidos complementando con el mensaje "El formulario está incorrecto, por favor verifique los campos obligatorios y/o el correo ingresado" |
| HU-19 | CA-19.1 | Informe personal de actividad | El informe (PDF via jsReport) incluye las alertas y acciones realizadas por el usuario principal y usuarios apadrinados | Si no hay datos necesarios para realizar un informe se entrega el mensaje "No existen registros para realizar un informe correctamente" y no se genera la descarga del archivo |
